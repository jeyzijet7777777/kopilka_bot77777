# kopilka_bot77777

Telegram-бот для бюджета «копилка»: дневной лимит, банк сдачи, накопительная копилка, графики и выгрузка в Excel.

## Запуск

1. Скопируйте `env.example` в `.env` и впишите `BOT_TOKEN` от @BotFather.
2. `pip install -r requirements.txt && python bot.py`

Docker: `docker build -t kopilka . && docker run -d --env-file .env -v kopilka_data:/app/data kopilka`
(без `-v ...:/app/data` данные пропадут вместе с контейнером, бот предупредит об этом администратора).

Локально без Docker: в `.env` задайте `DATA_DIR=.`, `DB_PATH=budget.db`, `STATE_PATH=bot_state.pkl`, `ALLOW_EPHEMERAL_DB=1`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен бота (обязательно) |
| `TZ_NAME` | `Europe/Moscow` | часовой пояс для дат, вечернего отчёта и расписания копий |
| `DATA_DIR` | `/app/data` (в Dockerfile) | точка монтирования постоянного тома |
| `DB_PATH` | `/app/data/budget.db` | файл SQLite, **должен лежать внутри `DATA_DIR`** |
| `STATE_PATH` | `/app/data/bot_state.pkl` | состояние диалогов |
| `ADMIN_IDS` | пусто | Telegram ID админов через запятую: `/admin`, `/backup`, `/restore`, предупреждения и копии |
| `EXPECT_EXISTING_DATA` | `0` | `1` = в базе уже есть данные, пустая база при запуске считается потерей |
| `STRICT_DATA_PATH` | `0` | `1` = не запускаться, если `DB_PATH` вне `DATA_DIR` |
| `ALLOW_EPHEMERAL_DB` | `0` | `1` = локальная разработка без тома, без тревог про путь |
| `SKIP_MOUNT_CHECK` | `0` | `1` = не проверять, что `DATA_DIR` смонтирован отдельным томом |
| `STARTUP_NOTICE` | `1` | сообщение админу при каждом запуске |
| `BACKUP_ENABLED` | `1` | еженедельная копия базы админам |
| `BACKUP_WEEKDAY` | `6` | день недели копии: 0=пн … 6=вс (или `mon`…`sun`, `пн`…`вс`) |
| `BACKUP_TIME` | `03:00` | время копии, `ЧЧ:ММ` по `TZ_NAME` |
| `BACKUP_KEEP` | `8` | сколько последних автокопий хранить на томе (`<DATA_DIR>/backups`) |
| `BACKUP_DIR` | рядом с базой, `backups/` | куда класть копии |
| `MONTH_REPORT_ENABLED` | `1` | автоотчёт за прошлый месяц 1-го числа (пользователь может отключить у себя в `/settings`) |
| `MONTH_REPORT_TIME` | `09:00` | время отправки 1-го числа, `ЧЧ:ММ` по `TZ_NAME` |
| `MONTH_REPORT_WINDOW_DAYS` | `3` | сколько первых дней месяца бот догоняет отчёт, если 1-го числа не работал |
| `WEEK_SUMMARY_ENABLED` | `1` | недельная сводка по понедельникам (пользователь может отключить у себя в `/settings`) |
| `WEEK_SUMMARY_TIME` | `09:00` | время отправки в понедельник, `ЧЧ:ММ` по `TZ_NAME` |
| `WEEK_SUMMARY_WINDOW_DAYS` | `2` | сколько первых дней недели бот догоняет сводку, если в понедельник не работал (1–6) |
| `LEGACY_DIR` | пусто | доп. папка, где искать старую `budget.db` / `bot_state.pkl` для переноса на том |

**Важно.** Переменные хостинга перебивают значения из Dockerfile. `DB_PATH=budget.db` (без `/app/data/`) на хостинге
означает базу внутри контейнера: при каждой пересборке она пропадает.

## Сохранность данных

1. База, состояние диалогов и копии лежат в постоянной папке `/app/data`.
2. При запуске бот пишет в лог путь и размер базы. Если `DB_PATH` не внутри `DATA_DIR`, том не похож на
   смонтированный, база пропала или пуста, а раньше в ней были данные, администратор получает предупреждение
   вместо тихого старта с нуля. «Раньше были данные» бот знает по маркеру `DATA_DIR/.kopilka_marker.json`
   (в нём запоминается состав базы). Если потерян весь том вместе с маркером, поможет `EXPECT_EXISTING_DATA=1`.
   Каждое стартовое сообщение содержит id тома и номер запуска: после потери тома номер сбросится в 1.
3. Раз в неделю бот сам присылает админам файл базы (согласованная копия через sqlite3 backup API, данные из
   WAL включены) и хранит последние `BACKUP_KEEP` копий в `backups/`.
4. `/restore` (только админ): пришлите файл `.db` (или `.db.gz`). Бот проверит сигнатуру, `integrity_check`, таблицы и
   версию схемы, покажет, что в файле, и **только после кнопки «Заменить»** заменит базу. Прежняя база
   сохраняется в `backups/before_restore_*.db` и присылается файлом. Лимит Telegram на скачивание ботом: 20 МБ.
5. **Перенос старой базы.** Если до этого база лежала рядом с `bot.py` (в рабочей папке, а не на томе), при первом
   запуске бот сам копирует `budget.db` и `bot_state.pkl` на том (`DATA_DIR`) и пишет администратору, что перенёс.
   Копирование идёт через sqlite3 backup API; **исходные файлы не меняются и не удаляются**. Существующую непустую
   базу на томе перенос никогда не затрагивает. Если на томе раньше уже были данные, а теперь пусто, старый файл
   молча не подставляется (он может быть старее): бот предупреждает, а нужную базу вы возвращаете через `/restore`.
6. Схема меняется только версионными миграциями (`migrations.py`, `PRAGMA user_version`). Перед миграцией
   непустой базы делается копия `backups/pre_migration_*.db`. База новее кода не открывается.

## Bothost (инструкция)

На Bothost при «Обновить из Git» контейнер пересобирается: пропадает всё, что лежит в `/app` мимо папки `data`
(по сообщениям пользователей Bothost; проверьте в панели, что `data` — постоянное хранилище вашего бота).
Поэтому база и состояние диалогов должны лежать в `/app/data`.

1. **Остановите бота** и скачайте из панели (файловый менеджер, «Скачать») `budget.db` и `bot_state.pkl`. Это страховка.
2. В файловом менеджере откройте папку `data` и **загрузите туда** эти два файла («Загрузить файл»). Оригиналы в корне не удаляйте.
3. В переменных окружения бота задайте (или исправьте, если уже есть другие значения):
   `DATA_DIR=/app/data`, `DB_PATH=/app/data/budget.db`, `STATE_PATH=/app/data/bot_state.pkl`,
   `ADMIN_IDS=<ваш Telegram ID>`. Переменные панели перебивают Dockerfile, поэтому `DB_PATH=budget.db` без `/app/data` нужно удалить.
4. Залейте новый код в Git и нажмите «Обновить из Git». Напишите боту `/start`: придёт сообщение о запуске с размером базы.
   Если вместо этого придёт «Старая база перенесена», значит бот нашёл `budget.db` в корне и скопировал её в `data`.
5. Проверьте `/admin` (число трат, копилка), затем добавьте `EXPECT_EXISTING_DATA=1`.
6. Проверка на пересборку: ещё раз «Обновить из Git». В сообщении о запуске номер запуска вырастет, а данные останутся.
7. Если придёт предупреждение «`/app/data` не похож на смонтированный том», а данные после обновления на месте, это ложная тревога
   (Bothost хранит папку не как отдельный диск): добавьте `SKIP_MOUNT_CHECK=1`. Если данные после обновления пропали,
   пришлите боту скачанный в шаге 1 файл через `/restore`.
8. Раз в неделю бот присылает файл базы вам в Telegram: это основная защита от потери самого хранилища.

## Отчёт за прошлый месяц

1-го числа после `MONTH_REPORT_TIME` бот сам присылает каждому настроенному пользователю итоги прошлого месяца:
доход, обязательные, потрачено из лимита, сдача или перерасход, дни с превышением, копилка на конец месяца,
топ-5 категорий и кнопку «Excel за этот месяц». Текст и цифры те же, что в «📚 Истории месяцев» (`/months`).
Если бот 1-го числа не работал, отчёт придёт при запуске в первые `MONTH_REPORT_WINDOW_DAYS` дней. Один раз на месяц:
факт отправки хранится в `settings` (`month_report_sent`), схема базы не менялась. Пользователь отключает отчёт
кнопкой «📅 Отчёт за месяц 1-го числа» в `/settings`. Не получают его те, у кого учёт начался позже этого месяца,
и те, кто заблокировал бота.

## Ввод

- Трата: `450 продукты`, `500 молоко`, `такси 300 вчера`, `1 500 перекресток 28.10`
- Фото чека: отправьте фото кассового чека — бот распознает QR-код (54-ФЗ) или текст «ИТОГО», определит дату, магазин и категорию!
- Банковские уведомления и СМС: отправьте текст вроде `Покупка 450р Пятерочка` или `Оплата 350 ₽ Додо Пицца` — бот автоматически запишет трату.
- В копилку: `+500 подработка`; из копилки — кнопка «💸 Из копилки»
- Команды: `/today /week /month /months /history /categories /chart /excel /piggy /settings /undo /help`

## Правка трат

`/history` или кнопка «🧾 Траты» (и список трат в «📊 Сегодня»): у каждой траты кнопка ✏️ открывает карточку с выбором
«💰 Сумму / 🏷 Категорию / 📅 Дату» и кнопкой удаления. Новое значение вводится сообщением (сумма: `450`; дата: `вчера`,
`28.10`, `28.10.2026`, будущие даты не принимаются; категория: текстом или кнопкой из уже использованных). `/cancel` или любая
кнопка меню отменяют ввод. Дневные лимиты прошлых дней от правки трат не меняются (они зафиксированы), банк сдачи и итоги
месяца пересчитываются сами.

## Графики за прошлые месяцы

Под каждым графиком есть кнопки «◀️ Окт 2026 / Ноя 2026 ▶️» и «📅 Месяц» (список всех месяцев с начала учёта); выбранный месяц
сохраняется при переключении вида графика. Из «📚 Месяцы» → месяц → «📈 Графики» открывается график этого месяца.
Для закончившегося месяца вместо прогноза показывается итог («потрачено X из Y, сдача/перерасход Z»), настройки месяца берутся
из его снимка (`month_settings`), как и в «📚 Месяцы».

## Предупреждения и недельная сводка

- **80% дневного лимита.** Когда трата впервые доводит сегодняшний день до 80% лимита (и лимит ещё не превышен), в ответ на
  запись добавляется строка «Потрачено 85% дневного лимита…». Превышение лимита и так видно в дневном отчёте. Тот же
  расчёт работает при правке суммы. Для трат задним числом предупреждений нет. Порог — `LIMIT_WARN_RATIO` в `bot.py`.
- **Недельная сводка.** По понедельникам после `WEEK_SUMMARY_TIME`: потрачено из лимита, сдача или перерасход, дни с
  превышением, самый дорогой день, сравнение с прошлой неделей, топ-3 категории, банк сдачи и копилка. Если за неделю не
  записано ни одной траты, сводка не отправляется. Отметка отправки хранится в `settings` (`week_summary_sent`).
- Оба вида включаются и отключаются в `/settings`.

## Категории и умное авто-распределение

- **Автоматическое определение:** бот знает тысячи товаров, брендов, заведений и магазинов. Напишите `500 молоко`, `300 шаурма`, `1200 пятерочка`, `2500 лукойл` или `800 нурофен` — бот автоматически запишет трату в подходящую категорию («Продукты», «Кафе и рестораны», «Авто», «Здоровье» и т.д.).
- **Адаптация под ваши категории:** если вы уже используете категорию «Еда» вместо «Продукты», бот подстроится под неё.
- **Обучение:** если бот определил категорию, под сообщением всегда есть кнопка с оригинальным словом. Нажатие на неё (или ручная смена категории) запоминается как ваше личное правило для будущих трат.
- **Настройка:** умное распределение категорий можно включить или выключить кнопкой «🪄 Умные категории трат» в `/settings`.
- Трата без категории (`450`) записывается как «Разное», а под ответом появляются кнопки с вашими чаще всего используемыми
  категориями, чтобы поменять её одним нажатием.
- Написание приводится к уже существующему: `ПРОДУКТЫ`, `продукты`, `Продукты` — это одна категория (`ё` = `е`).
- Если новая категория похожа на существующую (`продукт` и `Продукты`), бот сохраняет её как введено и предлагает кнопку
  «🏷 Продукты» для замены.
- `/categories` или «🏷 Категории»: расходы месяца по категориям с долей и изменением к прошлому месяцу, кнопки ◀️ ▶️ по
  месяцам и «📊 По месяцам» — таблица «категория × месяц» за последние 5 месяцев. Показаны обычные траты, без обязательных
  расходов и копилки. Из карточки месяца в «📚 Месяцы» есть кнопка «🏷 Категории месяца».

## Чтение чеков (QR-код и OCR)

- Отправьте боту **фотографию чека** (как фото или файл без сжатия).
- Бот автоматически:
  1. Считывает **QR-код чека** по стандарту ФНС (54-ФЗ) — моментально извлекает точную сумму и дату.
  2. Через **локальный OCR (RapidOCR)** находит название магазина (Пятёрочка, Магнит, ВкусВилл, Додо Пицца, Аптека и др.), строчку «ИТОГО» и товары.
  3. Автоматически присваивает категорию по магазину или товарам.
  4. Записывает трату и показывает кнопки быстрой смены категории или отмены.
- Работает полностью локально, без обязательных платных API или внешних сервисов. При наличии ключа `OPENAI_API_KEY` или `GEMINI_API_KEY` в `.env` может использоваться мультимодальный анализ для сложных чеков.

## Копилка

Баланс копилки накопительный: плановые отчисления за каждый месяц с начала учёта плюс все пополнения и снятия.
Пополнение уменьшает дневной лимит текущего месяца; снятие на лимит и банк сдачи не влияет и не может превышать баланс.

## Дневной лимит

Лимит прошедших дней фиксируется (таблица `day_limits`) перед любым изменением дохода, копилки, обязательных расходов
или числа дней. Изменение действует с сегодняшнего дня: оставшийся бюджет месяца делится поровну на оставшиеся дни,
поэтому сумма лимитов за месяц всегда равна «доход − обязательные − копилка», а прошлые дни не «краснеют» задним числом.

## Вечерний отчёт

Отправляется после выбранного времени, если за день ещё не уходил (в том числе после простоя бота).
При сбое отправки повторяется (до 5 попыток), пользователи, заблокировавшие бота, приостанавливаются до их первого сообщения.
Часовой пояс один на весь бот (`TZ_NAME`).

## История месяцев

Траты и пополнения копилки хранятся по датам и не удаляются. Кроме них бот сохраняет **снимок настроек каждого
завершённого месяца** (таблица `month_settings`): доход, обязательные расходы, плановую копилку и число дней.
Поэтому смена дохода или плана копилки в новом месяце не переписывает прошлые: сводка, банк сдачи, Excel и накопленная
копилка за старый месяц остаются прежними.

- Снимок делается автоматически: при смене даты (вечерняя задача) и непосредственно перед любым изменением настроек.
- Итоги месяца (потрачено, сдача, дни с превышением) считаются из трат на лету, поэтому правка старой траты сразу учитывается.
- Раздел «📚 Месяцы» (или `/months`): список всех месяцев с итогами, по нажатию — подробности и Excel за этот месяц.
- Месяцы, закончившиеся до появления архива, восстановлены по текущим настройкам и помечены знаком «≈».
- «Полный сброс всех данных» удаляет и архив.

## Админ-команды

Работают только для ID из `ADMIN_IDS`, остальным бот на них не отвечает. `/admin` показывает только агрегаты
(пользователи, активность, число трат, размер и путь базы, данные тома), личные суммы и траты не показываются.
`/backup` присылает согласованную копию базы файлом, `/restore` восстанавливает базу из присланного файла.

## Тесты

`pip install -r requirements-dev.txt && pytest`. Тесты работают на временных SQLite-базах:
проверяют правку трат, графики, предупреждения, недельные сводки, категории и безопасность миграций.
