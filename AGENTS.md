# Kopilka Bot (`kopilka_bot77777`) — Agent Guidelines & Architecture

Этот файл определяет правила, архитектуру и стандарты кодовой базы для ИИ-агентов Antigravity.

---

## 📌 Назначение проекта
**Kopilka Bot** — финансовый Telegram-бот персонального бюджета по системе «Копилка»:
- Учёт ежедневного лимита и банк сдачи.
- Накопительные цели («копилки») и переводы между ними.
- Визуализация: графики расходов на `matplotlib` (круговые диаграммы, динамика трат).
- Экспорт отчётов: выгрузка в Excel через `openpyxl` на основе `template.xlsx`.
- Автоматические отчёты: вечерние итоги, недельные сводки и месячные отчёты через `JobQueue`.
- Повышенная сохранность данных (`datasafe.py`): контроль монтирования томов в Docker, маркер целостности, горячие бэкапы через SQLite Backup API, безопасное восстановление (`/restore`).

---

## 🛠️ Технологический стек

- **Python**: 3.10+ (асинхронный код с строгой типизацией).
- **Telegram Framework**: **`python-telegram-bot[job-queue]` (v21.0 - v22.x)**:
  - Использовать `ApplicationBuilder`, `CommandHandler`, `CallbackQueryHandler`, `MessageHandler`, `ConversationHandler`.
  - Планирование задач через `context.job_queue` (`run_daily`, `run_repeating`).
  - **НЕ использовать** aiogram — проект строго на `python-telegram-bot`.
- **База данных**: SQLite3 с включенным режимом WAL (`PRAGMA journal_mode=WAL`).
- **Миграции**: собственный движок версионирования в `migrations.py`.
- **Графика**: `matplotlib` (обязательно с бэкендом `MPLBACKEND=Agg` для headless-рендеринга без графического дисплея).
- **Таблицы**: `openpyxl` (редактирование и генерация выгрузок по шаблону `template.xlsx`).
- **Тестирование**: `pytest` (`test_*.py` с моками в `conftest.py`).

## 📐 Архитектурные правила для агента

### 1. Изменение схемы базы данных (`migrations.py`)
- Любые изменения таблиц (добавление колонок, индексов, новых сущностей) производить **только** через `migrations.py`.
- Никогда не выполнять сырые `ALTER TABLE` / `CREATE TABLE` внутри обработчиков `bot.py`.
- Всегда увеличивать версию схемы и гарантировать обратную совместимость, чтобы база пользователя не ломалась при обновлении.

### 2. Сохранность данных (`datasafe.py`)
- Бот критически зависит от постоянства файла `DB_PATH`.
- Не удалять и не перезаписывать файлы БД напрямую без создания бэкапа (`sqlite3.backup`).
- Все операции записи должны выполняться в транзакциях.

### 3. Обработка дат и часовых поясов
- Всегда учитывать часовой пояс `TZ_NAME` (по умолчанию `Europe/Moscow`).
- Расписания автоотчётов и граница наступления нового дня должны рассчитываться строго по локальному времени пользователя.

### 4. Генерация графиков (`matplotlib`)
- Всегда закрывать фигуры `plt.close(fig)` после генерации PNG в `io.BytesIO()`, чтобы предотвратить утечки оперативной памяти на сервере.
- Использовать headless-бэкенд `Agg`.
